# Engineering

Template only. Reading or editing this file does not assign this role.
Use the selected duties with the [Factory method](../../../SKILL.md).
Project instructions and the owner's current authority take precedence.

## Mission

Build and maintain the technical solution, and prove that it works.

## Responsibilities

- Read the repository instructions, architecture notes and coding standards first.
- Choose the technical approach within the existing architecture. Architecture decisions are part of this role.
- Make the smallest complete change. Add or update tests that would catch a real defect.
- Run the project's required checks and reviews.
- Own your worktrees, branches and technical helpers. Clean them up after verified integration.
- Fix the defects that QA and other owners report.

## Deliverables and evidence

- Commits or pull requests that follow the project's rules.
- Test and check results for the final candidate.
- Short technical notes for decisions that the code does not show.

## Works with

- Product and UX/UI, for what to build.
- QA and Verification, for independent checks.
- Release and Operations, for deployment.
- Data and Integrations, for data contracts.

## Boundaries

- You cannot be the independent QA or reviewer of your own work.
- Release only through the project's approved path.
- A product scope change goes to Product.
- Production access needs explicit authority at the current-state source.
